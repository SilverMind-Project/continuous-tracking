# wear-companion

Standalone Wear OS companion app (`continuous-tracking/wear-companion/`, Kotlin + Gradle 8.12.1) that lets a resident or caregiver's smartwatch (such as a Pixel Watch 5) serve as a dual-mode identity wearable:

- **Tier 1 (default, always-on BLE beacon):** continuous static iBeacon advertising (`0x004C` Apple/iBeacon manufacturer payload, 2 Hz on-body, 1 Hz screen-off, stopped immediately off-body) picked up by fixed room BLE receivers.
- **Tier 2 (opt-in `dualMode` flavor, UWB burst controller):** motion-duty-cycled 12-second FiRa 2.0 UWB ranging bursts triggered on walking locomotion, capped by a token-bucket battery and thermal guard (120 s/h, 20% SoC cutoff), and published as 3-second JSON micro-batches (`device_ranging.v1`) over LAN MQTT to `rf-ingress`'s `device_ranging_mqtt` adapter.

## Non-negotiable rules

1. **Pure-Kotlin `:core` owns all logic.** All state machines, frame encoding, STS payload framing, battery budget limits, and batch serialization live in `core/src/main/kotlin/io/silvermind/wearcompanion/core/` (`kotlin("jvm")`, zero Android SDK imports) so `make wear-check` runs natively on Linux `aarch64` and `x86_64` CI without requiring an Android SDK.
2. **Runtime grants are requested, never assumed.** `RequiredPermissions` (`app/src/main/kotlin/io/silvermind/wearcompanion/app/RequiredPermissions.kt`) lists the dangerous permissions of the build (`BLUETOOTH_ADVERTISE` and `BODY_SENSORS`; `dualMode` adds `UWB_RANGING` and `ACTIVITY_RECOGNITION`, which the step detector needs). `PairingActivity` requests the missing ones and shows which are still missing; the service treats a missing advertise grant like Bluetooth off, skips the step detector without its grant, and logs once instead of crashing. Every Bluetooth advertiser call is guarded against `SecurityException`, because the wake-frame restore runs on the main thread.
3. **Tier 1 zero-network manifest invariant.** `app/src/main/AndroidManifest.xml` (`bleOnly` flavor) declares ONLY `BLUETOOTH_ADVERTISE`, `BODY_SENSORS`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_CONNECTED_DEVICE`, and `RECEIVE_BOOT_COMPLETED`, with `android:allowBackup="false"` and standalone Wear OS metadata. It must NEVER declare `INTERNET`, `ACCESS_NETWORK_STATE`, `CHANGE_WIFI_STATE`, `UWB_RANGING`, `WAKE_LOCK`, or `ACTIVITY_RECOGNITION` (Tier 1 has no locomotion sensors). `core/src/test/kotlin/io/silvermind/wearcompanion/core/ManifestPermissionsTest.kt` enforces this invariant on every `make wear-check` run.
4. **Tier 2 stays opt-in at build time AND runtime.** UWB and LAN MQTT permissions live exclusively in `app/src/dualMode/AndroidManifest.xml`, and `app/src/dualMode/kotlin/io/silvermind/wearcompanion/app/uwb/Tier2Provider.kt` stays in `BLE_ONLY` unless `tier2_config.json` (`FileTier2ConfigStore`) is present, enabled, and valid (gated on physical device probe sign-off). The file is written only by `Tier2ProvisioningReceiver`, a `dualMode`-only exported receiver protected by `android.permission.DUMP` so only the ADB shell can provision it; never add an unguarded exported component that accepts a broker URL or key. The config accepts only an 8-byte Static STS key (both engines use multicast DS-TWR, Play services `CONFIG_ID_2`), and every anchor must share one channel and preamble. Provisioned `anchor_id`s must equal the Cognitive Companion node `anchor_id`s, because `rf-ingress` uses a non-empty `anchor_id` verbatim.
5. **Never log PII or secrets.** The watch holds only its anonymous beacon UUID/major/minor and optional `tag_id` plus LAN broker config. Never store household member names, floor-plan coordinates, or cloud credentials on the watch, and never log STS keys or MQTT passwords.
6. **Monotonic timestamps, multi-anchor round aggregation, and burst clock decoupling.** Android UWB callbacks (`onRangingResult(device, position)`) fire once per peer anchor per ranging round. `MultiAnchorRoundAggregator` in `:core` must coalesce peer readings within `roundWindowMs` (150 ms) into a single multi-anchor `RangingEpochSample` sharing one `epochSeq` (never incrementing `epochSeq` per peer callback, which would split rounds into 1-anchor epochs and prevent multilateration). `EpochBatchPublisher` (`core/src/main/kotlin/io/silvermind/wearcompanion/core/EpochBatchPublisher.kt`) converts monotonic `elapsedRealtimeNanos` into strictly monotonic `measured_at_unix_ns` using a boot-time Unix nanosecond anchor, and stamps top-level `sent_at_unix_ns` on every MQTT flush so `rf-ingress`'s `BurstClockOffsetTracker` decouples 3-second micro-batching delay from clock skew.
7. **Hardware stops at the engine interface, and cold flows must be actively collected.** `UwbRangingEngine` (`core/src/main/kotlin/io/silvermind/wearcompanion/core/UwbRangingEngine.kt`) isolates `:core` from Android UWB APIs. `:app`'s `dualMode` flavor implements `GmsNearbyUwbEngine` (primary) and `JetpackUwbEngine` (fallback); each emits raw per-peer callbacks through the `:core` `coalesceRounds` operator, and `:core` tests inject `FakeUwbRangingEngine` (a cold flow that reports ranging active only while collected). `CompanionCoordinator` serializes every public method behind one `Mutex`, runs each burst as a job in its required `CoroutineScope` (prepare, 12-byte BLE wake frame under manufacturer ID `0xFFFF` with the `SM` magic, 300 ms wait, then collect `startRanging` into `onUwbEpoch`), re-checks a burst generation after every suspension, and stops a burst by stopping the engine and flushing before it cancels the job (a burst usually ends inside its own collector). Both engines coalesce on `Dispatchers.Default` (`flowOn`) so a blocking MQTT reconnect on the service thread cannot split a round. `CompanionForegroundService` runs the coordinator on one serial dispatcher, routes every Tier 2 reload through one conflated channel (single flight), sends a 1 Hz `onTick` only while Tier 2 is active (it advances burst and cooldown timers and flushes leftover epochs), and holds a `dualMode` wake lock (`BurstWakeHold`) for each burst. Each burst uses a random positive FiRa session ID so two watches never share one.
8. **Wire contract parity.** Every field name and enum value in `DeviceRangingV1Batch` (`core/src/main/kotlin/io/silvermind/wearcompanion/core/EpochBatchPublisher.kt`) and `core/src/main/kotlin/io/silvermind/wearcompanion/core/RuntimeMode.kt` must stay in lockstep with `DeviceRangingV1Payload` in `rf-ingress/rf_ingress/adapters/device_ranging_mqtt.py` and `cts_contracts.wearables` (`unspecified`, `on_body`, `off_body`; `unspecified`, `moving`, `still`; `uwb`, `ble_channel_sounding`, `ble_rssi`).

| `core/src/main/kotlin/io/silvermind/wearcompanion/core/LocomotionDutyCycleFsm.kt` | Tier 2 5-state walking-trigger FSM (`OFF_BODY`, `ON_BODY_STILL`, `LOCOMOTION_CANDIDATE`, `UWB_RANGING_BURST` 12 s max, `BURST_COOLDOWN` 60 s same-walk / 10 s stop-walk reset) with fidget filter (`>= 3` steps in 4 s + accel variance `[0.8, 15.0]` m^2/s^4) |
| `core/src/main/kotlin/io/silvermind/wearcompanion/core/BatteryBudgetLimiter.kt` | Token-bucket UWB guard (120 s capacity, 120 s/h refill = 3.3% max duty cycle), 20% battery cutoff, and `MODERATE` thermal cutoff |
| `core/src/main/kotlin/io/silvermind/wearcompanion/core/PreSharedStsNegotiator.kt` | Static STS key parts and the exact 12-byte big-endian BLE wake payload advertised under `WAKE_MANUFACTURER_ID` (`0xFFFF`): magic `0x53 0x4D`, `version=0x01`, `sessionId:u32`, `controllerAddress:u16`, `channel:u8`, `preambleIndex:u8`, `burstDurationS:u8` |
| `core/src/main/kotlin/io/silvermind/wearcompanion/core/MultiAnchorRoundAggregator.kt` | Coalesces per-peer UWB callbacks into one multi-anchor epoch per round (150 ms window, duplicate-anchor and all-anchors closes), `EpochSequence` monotonic across bursts, and the `coalesceRounds` flow operator with a 50 ms partial-round flush timer |
| `core/src/main/kotlin/io/silvermind/wearcompanion/core/EpochBatchPublisher.kt` | 60-epoch in-memory ring buffer, monotonic `measured_at_unix_ns`, 3 s `device_ranging.v1` JSON micro-batch flush to `rf/devices/{tag_id}/ranges`, doubling retry backoff (to 30 s) after a failed publish |
| `core/src/main/kotlin/io/silvermind/wearcompanion/core/Tier2ConfigStore.kt` | `tier2_config.json` model, validation (broker URL, 8-byte key, unique anchors on one channel), base64 decode for ADB, and the atomic owner-only `FileTier2ConfigStore`; errors and `toString` never contain secrets |
| `core/src/main/kotlin/io/silvermind/wearcompanion/core/CompanionCoordinator.kt` | Composes Tier 1 BLE, Tier 2 locomotion FSM, budget limiter, `UwbRangingEngine`, `EpochBatchPublisher`, and `BurstWakeHold`; owns the burst job lifecycle |
| `app/src/main/AndroidManifest.xml` | Base `bleOnly` manifest (strictly zero network and zero UWB permissions) |
| `app/src/dualMode/AndroidManifest.xml` | Opt-in `dualMode` permission overlay (`UWB_RANGING`, `WAKE_LOCK`, `INTERNET`, `ACCESS_NETWORK_STATE`, `CHANGE_WIFI_STATE`) |
| `app/src/main/kotlin/io/silvermind/wearcompanion/app/` | `BleBeaconTransmitter`, `OffBodySensorMonitor`, `CompanionForegroundService`, `PairingActivity` (also requests runtime permissions), `RequiredPermissions`, `BeaconStatusTileService`, `BootCompletedReceiver` |
| `app/src/dualMode/kotlin/io/silvermind/wearcompanion/app/uwb/` | `GmsNearbyUwbEngine`, `JetpackUwbEngine`, `MqttBatchTransport`, `Tier2Provider` (reads `tier2_config.json`), `Tier2ProvisioningReceiver` (DUMP-guarded ADB `PROVISION_TIER2` / `CLEAR_TIER2` / `RELOAD_TIER2`, reloads the running service in process), `PowerManagerBurstWakeHold` |

## Quality gates

- Format: `make wear-format` (`./gradlew :core:ktlintFormat --no-daemon`)
- Lint: `make wear-lint` (`./gradlew :core:ktlintCheck :core:detekt --no-daemon`)
- Tests: `make wear-test` (`./gradlew :core:test --no-daemon`, JUnit 5)
- Module gate: `make wear-check` (also wired into `make check-all`, `make ci`, pre-commit, and CI `wear-check` job)
- Building Wear OS APKs on a host with an Android SDK (compileSdk 36, AGP 8.9.1, `ANDROID_HOME` set): `./gradlew :app:lintBleOnlyDebug :app:lintDualModeDebug :app:assembleBleOnlyDebug :app:assembleDualModeDebug --no-daemon`. This aarch64 dev box has no Android build tools, so run it on the Windows build PC with `../cognitive-companion/scripts/ccwin wear-build [--allow-dirty] [--probe]` (fetch logs and APKs with `ccwin fetch latest`).
- Provisioning Tier 2 on a watch (`dualMode` build): `adb shell am broadcast -n io.silvermind.wearcompanion/io.silvermind.wearcompanion.app.uwb.Tier2ProvisioningReceiver -a io.silvermind.wearcompanion.PROVISION_TIER2 --es config_b64 "$(base64 -w0 tier2_config.json)"`; the broadcast result line reports whether the config was accepted.
