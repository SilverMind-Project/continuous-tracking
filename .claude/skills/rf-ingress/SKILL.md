# rf-ingress

Hardware-neutral Python ingestion service (`continuous-tracking/rf-ingress/`, port `8095`) that turns RF hardware or simulator inputs into validated `TagFix` protobuf messages on `wearable.fixes` and `AdapterCapability` heartbeats on `wearable.capabilities`.

## Non-negotiable rules

1. **Hardware stops at one adapter module.** Every radio or vendor format sits behind one adapter module under `rf_ingress/adapters/` implementing `RangeAdapter`, `PositionAdapter`, and/or `RoomAdapter` (`rf_ingress/adapters/base.py`). Vendor payload Pydantic models live inside that module and are selected by a versioned `payload_profile`. No code outside an adapter names a vendor or firmware; downstream code branches only on declared capability and covariance.
2. **Conformance kit is the definition of "adapter done".** Every adapter (present and future) adds a factory case in `tests/conformance/conftest.py` and must pass `tests/conformance/test_adapter_conformance.py` unchanged.
3. **Per-epoch fixes only; never smooth across epochs, and always flush expired open epochs on a background timer.** `EpochBuilder` (`rf_ingress/solver/epoch.py`) groups ranges per `(adapter_id, tag_id)` by explicit `epoch_seq` or `epoch_window_s` (0.25 s) of device `measured_at`, but expires them on the **server clock**: `add(measurement, now=arrival)` records arrival time and `flush_expired(now)` closes epochs idle for `epoch_window_s` (or open longer than `max_open_s`, default 2 s). Never expire on device `measured_at`: a `device_ranging.v1` micro-batch arrives up to 3 s after capture, and a flush tick between two measurements of one batch would split it. `RfIngressRuntime` (`rf_ingress/pipeline.py`) runs `_epoch_flush_loop` every `epoch_flush_interval_s` (default `min(0.05, epoch_window_s / 4)`) calling `flush_expired_epochs()`, which logs and counts (`DropReason.PUBLISH_FAILED`) a failed epoch instead of dying, so the final epoch of a duty-cycled UWB burst publishes within `epoch_window_s`. An epoch also closes early when every expected node of the adapter reported, or, for unbatched senders only (no `sent_at`), when all nodes of one room (at least 3) reported and no node outside that room was heard; a batch delivers the whole round at once, so room completion there would turn the rest of the same message into dropped stragglers. A late measurement repeating the explicit `epoch_seq` of an epoch closed within `straggler_horizon_s` is dropped (`DropReason.LATE_EPOCH_MEASUREMENT`) rather than reopening a duplicate epoch; only an exact repeat counts, never `seq <= last_closed`, because device and adapter restarts reset counters. `tracking-orchestrator` is the only temporal filter in the chain.
4. **Wearables are identity evidence only.** `rf-ingress` never drops `OFF_BODY` fixes (it passes `wear_state` and `motion_state` through truthfully so CTS decides). A missing fix is never evidence of absence.
5. **Accuracy is covariance, with 3D-to-2D vertical-conditioning fallback.** Every `RangeMeasurement` (`rf_ingress/domain.py`) carries a required positive `variance_m2`; the solver inflates it to `variance_m2 / max(min_los_confidence, los_confidence)^2` (`min_los_confidence` 0.15, at most about 44x) everywhere it weights a range (`effective_variance_m2`), and adapters never fold `los_confidence` into `variance_m2` themselves. Every measurement also carries a closed `RangingTechnology` (`ble_rssi`, `ble_channel_sounding`, `uwb` from `cts_contracts.wearables`). `MultilaterationSolver` (`rf_ingress/solver/multilateration.py`) weights strictly by that effective variance, never branches on technology, and never drops wide-covariance fixes (`max_sigma_m: null` by default). When a 4+ anchor 3D solve is ill-conditioned along the vertical axis (`cond_3d > max_condition`), the solver must automatically fall back to the 2D fixed-height solve (`assumed_tag_height_m=1.0`, `tag_height_sigma_m=0.3`) before rejecting an epoch.
6. **Wrist-local azimuth is telemetry only.** `MultilaterationSolver` ignores `azimuth_deg` whenever `azimuth_reference_frame != "floor_plan"` (including `"device_local"` from wrist-worn watches) so 3+ anchor distance solves are invariant to wrist rotation. Optional bearing residuals apply only when 2 fixed anchors report calibrated `"floor_plan"` bearings.
7. **Core room fallback and position room attribution.** When an epoch has fewer than 3 known RF nodes (or multilateration fails to converge), `room_fallback_from_epoch` (`rf_ingress/solver/epoch.py`) emits `FIX_KIND_ROOM` for the nearest node's `room_id` with margin-based `room_probability`. When multilateration succeeds (`FIX_KIND_POSITION`), `infer_epoch_room` stamps `EmittedFix.room_id` **and** `room_probability` from the nearest inlier node's room (the solver's dropped outlier anchor is excluded), using the same margin rule as the room fallback, so uncalibrated cameras in that room can still consume room-level evidence. Never stamp a room without a probability: CTS `room_distribution_for_fix` reads a POSITION `room_id` without `room_probability` as certainty when it has no room polygons. With no node room, `room_id` stays `""`.
8. **Site-config revision atomicity and bounded clock offset tracking.** `HttpSiteConfigClient` (`rf_ingress/site_config.py`) polls CC `GET /api/v1/wearables/site-config` with `X-API-Key` every 60 s and keeps the last valid snapshot on errors. Whenever `version` changes, `EpochBuilder.on_site_config_version` drops all open epochs so no solve mixes nodes from two floor-plan revisions. `BurstClockOffsetTracker` (`rf_ingress/clock.py`) expires delay samples older than `max_sample_age_s` (1800 s), but keeps the best expired sample as the reference until `step_confirm_batches` fresh batches exist, so the first (Wi-Fi wake) batch of a burst after a long idle never sets the offset alone. A downward step is adopted at once by `min()`. An upward step resets the window only after `step_confirm_batches` (2) consecutive batches all exceed the window minimum by `step_reset_threshold_s` (0.75 s) and agree within `step_consistency_s` (0.5 s). Never reset on a single high sample: a backlog delivered late is indistinguishable from a clock step for one batch, and resetting would make stale data look fresh. At most `max_tracked_tags` (256) tags are tracked, least recently seen evicted first.
9. **Fail-closed registration and binding gate.** `RegistrationGate` (`rf_ingress/registration.py`) publishes a fix only when a site-config snapshot is loaded, the `tag_id` is registered and `is_active`, and a binding covers `measured_at` (`[valid_from, valid_to)`).
10. **Privacy and bounded labels.** Raw fixes on `wearable.fixes` are trimmed with `XADD ... MINID ~ <now - 72h>` (`rf_ingress/publish.py`). Logs use `structlog` and never tie positions to member IDs. Enum Prometheus labels (`ReportKind`, `DropReason`, `FixKind`) are closed `StrEnum`s in `rf_ingress/observability.py`; member IDs never appear in any metric label.

## How to add a hardware adapter

1. Create one module `rf_ingress/adapters/<name>.py` implementing `RangeAdapter`, `PositionAdapter`, or `RoomAdapter` with strict Pydantic v2 config and versioned `payload_profile` models inside that module.
2. Drop and count unregistered hardware keys/tags (`UNREGISTERED_TAG_TOTAL`, `DropReason.UNREGISTERED_TAG`) and malformed payloads (`DropReason.MALFORMED_INPUT`) without ever raising out of the async iterator.
3. For burst-batched senders (such as `device_ranging.v1`), populate `RangeMeasurement.sent_at` from the batch flush timestamp and `measured_at` from the per-epoch capture timestamp so `BurstClockOffsetTracker` decouples queueing jitter from clock skew.
4. Register the factory in `rf_ingress/adapters/registry.py`.
5. Add a conformance case to `tests/conformance/conftest.py` and adapter unit tests with pinned sample payloads.
6. Verify `make rf-check` and `make ci` pass without changing any file under `tracking-orchestrator/app/`.

## Streams and gates

- `wearable.fixes`: field `"fix"`, raw `TagFix` protobuf, `MINID` trimmed to 72 hours.
- `wearable.capabilities`: field `"capability"`, raw `AdapterCapability` protobuf, 60 s heartbeat.
- Fast gate: `make rf-check` (ruff check, ruff format --check, mypy strict, import-linter, unit + conformance pytest).
- Full gate: `make ci` (includes `make rf-test-integration` against a Redis testcontainer).
- Use `rf-ingress/.venv/` (Python 3.12), never system Python. Sync with `cd rf-ingress && uv sync --frozen --extra dev`.
